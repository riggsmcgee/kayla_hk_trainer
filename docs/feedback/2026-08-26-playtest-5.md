# Playtest 5 — user notes (2026-08-26)

The first playtest of the playtest-4 build (branch `proactive/2026-08-25-2008`). Nine notes: three
picks from the portfolios, five changes to the Two Bills and the finale, and the first request for
controller support. Settled over two rounds of `/grilling` on 2026-08-26.

**Everything under "Ratified decisions" is a decision, not a suggestion — do not re-open it without
the user.** Where a decision strikes something an earlier round ratified, the struck line is quoted
so nobody has to guess whether the contradiction was noticed.

## The arithmetic the interview turned on

Two rounds of this interview were decided by numbers rather than opinions, and one of those numbers
was **wrong when first presented and corrected mid-interview**. Both are recorded here because the
build depends on them and because the correction is the more useful of the two.

### The volley strip is 47–128 px above the FLOOR

`activeNailHitbox`'s `up` case builds its box at `y − KNIGHT.spriteHeight − PHYSICS.nailReachUp` with
height `nailReachUp`. `y` is her **feet**, so standing on the floor the box spans **48–128 px above
the floor** — that is 0–80 px above her 48 px head, not 48–128 above it. Her hurtbox top is at 47 px.
So the strip in which the ball can be struck before it has reached her is **[47, 128] — 81 px deep**.

Playtest 4's contract and `arena.ts`'s own comment both say "a band 48–128 px above her head". **That
prose is wrong**; the 81 px figure it quotes is right. Correct the prose, keep the number.

### The two thresholds that decided the roll's height

|                                       | value             | why                                                                                             |
| ------------------------------------- | ----------------- | ----------------------------------------------------------------------------------------------- |
| Her max jump, fully held              | **233.3 px**      | `jumpVelocity` 666 pinned for `jumpHoldMax` 0.18 s, then a ballistic coast under `gravity` 1900 |
| Her jump if she taps                  | **55.5 px**       | the pin's 5-step minimum, then the cutoff eats the coast                                        |
| **Jumping over the ball dies at**     | **apex 175.3 px** | the ball is 58 px tall; her feet must clear `apex + 58`                                         |
| **The floor-standing volley dies at** | **apex 188.9 px** | above this the ball crosses the 81 px strip in under `nailActiveTime` 0.15 s                    |

**There is no height that both kills the jump-over and keeps the volley comfortable** — the two
thresholds are 13.6 px apart. Everything in note 1 follows from choosing inside that band.

Volley window by apex, for reference: 147 px (Loper's tall arc today) → 0.205 s = 1.37 nail windows;
150 px (the current cap) → 1.33; 180 px → ~1.05; 188.9 → 1.00; 233 px → 0.82.

## Ratified decisions

### The roll (note 1)

- **Every bounce is the same height. The alternation is gone.** This **strikes** a playtest-4 line:
  _"Every variant must alternate, so each one keeps a low phase the volley can live on."_ `PLAN.md` §3
  must be corrected, not appended to.
- **The apex is 180 px**, and `ATTACKS.dog.rollApexMax` (150) is **struck** with it. 180 sits above the
  175.3 px jump-over threshold and below the 188.9 px volley threshold — the only band where both of
  the user's goals survive. The launch speed for it is √(2·1500·180) ≈ **735 px/s**.
- **Accepted consequence: the roll gets less dangerous.** The 30 px skitter was the only part of
  Loper's cycle a Knight standing still was not safe under, and deleting it removes most of the roll's
  standing threat. The user accepted this knowingly — **Bill the man is the pressure**, and the roll is
  a positioning-and-rhythm beat.
- **Loper's `speedX` rises from 205 toward 300** (and `speedXHot` in proportion). At 205 she simply
  outruns it — `runSpeed` is 332 — and outrunning it was the whole counter once the low bounce is gone.
- **What "keep the Loper's movement" means is CADENCE AND ARC SHAPE, not apex.** The user could not
  recall the near-misses, so the usual "measure what the chosen ones have in common" step could not be
  run on the entrance or the look; for the roll it was derived from the note itself and the user
  delegated the call. If a future variant needs tuning, preserve the slow lazy rhythm, not the number.

### The uncurl (notes 2 and 6's second half)

- **`rollTime` becomes a soft threshold, not a hard stop.** After it elapses the dog _wants_ to land,
  and actually uncurls **on the next floor contact**. He never uncurls in mid-air, and the floor never
  moves to him.
- **The uncurl is a ~0.5 s animation and he is LETHAL throughout it.** The user overrode a proposed
  harmless punish window: _"make his hitbox active so that she can't just walk into the dog. He should
  be lethal at this point."_ This keeps playtest 4's _"no exceptions and no immunity window"_ intact
  rather than reintroducing it in a new costume.
- **`renderBillDog.ts` already contains a fully-drawn `'walkIn'` pose that `billDogPose` can never
  return.** It is the obvious candidate for the animation.
- **Build this BEFORE the taller arc.** The teleport is a per-variant constant — Loper drops 12.5 px
  today — and a uniform max-height arc takes it to ~223 px. Doing note 1 first ships the exact
  complaint, an order of magnitude worse, on the variant the user picked.

### The roll's duration (note 2)

- **`rollTime` 5.0 → 7.0**, and **`rollEvery` 6.5 → 5.0** so the cycle stays near 12 s rather than
  stretching to 14. The ratified pressure knob is the gap between rolls, and raising the roll length
  alone would have loosened it.
- **No overrun cap.** See the volley below.

### The volley may keep him up forever (new)

- **An indefinite juggle is SANCTIONED, as an Easter egg.**
  > _"Let's let him be indefinitely viable as a fun Easter egg because you have to remember, Bill the
  > man is also attacking her this whole time. The odds of her being able to hold on to an infinite
  > volley are very slim."_
- This **strikes** playtest 4's _"The 5 s roll timer keeps running during a rally, so it delays where he
  lands but can never become a stall."_ The reasoning that replaces it: the fight does not pause while
  she juggles, so an infinite volley is a thing she is surviving, not a thing she is hiding behind.
- **The ball needs a ceiling bounce.** `stepRoll` has no ceiling test at all, and `bossWorld()`'s lid
  would be found by `blockerOf` as a **horizontal wall**, snapping the ball outside the arena. Sanctioning
  the juggle makes that reachable. It bounces off the lid, the same way the bones already do.

### The end screens (note 4)

- **Four screens, one root cause: every end-screen guard is shorter than the input rhythm she is
  already in.** `OVERLAY_LOCKOUT_SECONDS` is 0.35 s; `PHYSICS.nailCadence` — the rate a mashed attack
  re-fires — is 0.41 s. The guard loses by 0.06 s, every time.

  | screen                      | guard today                                                           |
  | --------------------------- | --------------------------------------------------------------------- |
  | Pogo course clear           | 0.35 s lockout, defeated by the next pogo press                       |
  | **Finale wave stage-clear** | **none — `advance()` fires on a 2 s timer with no input at all**      |
  | Finale wave fail            | none; the 0.15 s hit-stop is assumed to absorb the press and does not |
  | Boss fail                   | none, same assumption                                                 |

- **The fix is a FRESH PRESS, not a longer lockout**: a screen may only be dismissed by a key that
  goes **down after the screen appeared**. A time lockout is a guess about how fast she is mashing;
  this stops guessing, and it lets the lockout stay short so no screen feels sticky.
- **The wave stage-clear auto-advance is deleted outright.** It is the only one that needs no input
  whatsoever, and it is the purest form of the complaint.

### Wave 2 (note 5)

- **"The second duelist challenge" is the finale's wave 2, "The real ones".** Both natural readings
  land there; wave 1 has no duelist and the Colosseum has no reinforcements.
- **The reinforcements become spitter + warden**, so the cast at 0:30 is **two spitters, a duelist and
  a warden — exactly the spread the user named, and exactly `ARENA_MAX_ALIVE` (4).** The alternative
  reading (four arrivals _on top of_ the opening pair, six alive) was rejected: it contradicts the
  user's own playtest-4 sentence _"the enemies increase from two to four at 30 seconds"_, and with the
  cap left at 4 the runtime would have **silently deleted the duelist and the warden** while every test
  stayed green.
- **`hitsRequired` stays 6.** It is summed over the opening cast only, by construction.
- **The two spitters must be visibly separate.** `joinX` has no slot term, so simultaneous arrivals land
  at the identical point, and unlike the flier twins a spitter's bob is vertical-only — they would read
  as one body forever.

### Bill the man (note 6)

- **Jumping remains the correct answer to the lance. It stops being free.**
  > _"She obviously is meant to jump over the dash attack, but if he's in the wind-up for it and she's
  > already trying to jump over him, he should react to that and do a proper anti-air."_
- **The conversion happens EARLY and re-tells.** During roughly the first half of the lance telegraph,
  if she is airborne and in front of him, he aborts the lance and shows a **fresh swat telegraph**. She
  gets the full swat tell before the swat, so the tell she acts on is never a lie — preserving the
  ratified _"heat is speed and gaps, never a shorter tell"_. A conversion that fired after she had
  committed was considered and rejected for exactly that reason.
- **Separately, a live defect to close**: the second lance pass re-enters `telegraph` from `recovery`
  **without passing through `idle`**, so the "never lance while she is above his head" gate never runs
  on it. He already lances out from under a Knight standing on his head, which `PLAN.md` forbids.
- **Re-aiming the second pass is a no-op and must not be built.** `chargeIntoWall` parks him flush
  against a wall, so "toward her" and "reverse" are always the same direction.

### The picks (note 3)

- **Heavy** is the entrance. It is already `BILL_ENTRANCES[0]`, so this authorises deletion later and
  changes no runtime behaviour now.
- **Stepped bones, plain ring.** "Stepped" bundles `boneSteps: 8` (which is the no-interpolation rule
  holding) with a broken `'spun'` ring (which only makes the marker quieter — all three looks already
  use a stepped ring). The user wanted the bones. **A fourth combination is needed**: stepped bones on
  the plain ring.
- **Reorder the defaults so a fresh browser gets the picks.** Every fallback resolves to index 0 today,
  so a clean install currently plays the **smooth** bones — the version that breaks the rule the user
  just voted to keep.
- **The pickers stay one more round.** The roll is about to change substantially and the user will want
  to compare the new one against Loper-as-it-was before anything is baked in.

### The controller (note 7)

- **Nothing is broken; the feature does not exist.** There is no Gamepad API code anywhere in the
  project. `input.ts` is keyboard-only and `SettingsV1.inputBindings` is explicitly groundwork for a
  later milestone.
- **The user tests keyboard mode FIRST.** A leverless in keyboard mode would already work today with
  zero code changes. "Nothing happened at all" is only consistent with an HID pad emitting no key
  events — and that single test could save the entire milestone.
- **Then: a gamepad reader behind the existing `InputFrame` seam**, so nothing else in the game learns
  what a gamepad is, plus a "press any button" detector in Settings.
- **The Switch constraint is load-bearing.** `PLAN.md` scopes gamepad support to Kayla's muscle-memory
  transfer to the Switch, and `ControllerDiagrams` draws her board **in Switch mode**. A PC button
  profile reports a different order, so practising here on the wrong map would make the feature
  actively harmful to the pillar it exists to serve.
- Note that playtest 1 ratified M7 as **"not an autonomous-session task"**, because the acceptance test
  is a human holding the board. An unattended sprint can build the seam; it cannot close the loop.

## Documentation defects, to fix in passing

Found while verifying the above; none of them needs a decision.

- `PLAN.md`'s wave table still says **0:45** for wave 2's second arrival. Both the code and the
  playtest-4 contract say 0:30.
- `PLAN.md`'s _"three tests pin it, so no future tuning can quietly delete the mechanic"_ is **one**
  test — and that test builds the volley band 48 px too high, so it would have passed the change note 1
  asks for. The claim was false when written.
- `arena.test.ts`'s "leaves 81 px of headroom" asserts **70**. It subtracts the dog's height from a
  feet-anchored apex, which yields the ball's **top**, not its underside.
